## สายงาน — ใครส่งงานให้ใคร

### สายเนื้อหา (ไหลทางเดียว ห้ามข้ามด่าน)

```
lesson-designer   ──┐
                    ├──► content-reviewer ──► next-dev (นำเข้าระบบ) ──► ครูกดเผยแพร่
exercise-writer   ──┤
art-prompt-writer ──┘
```

**จุดสำคัญ:** `content-reviewer` คือด่านเดียวที่มีสิทธิ์ตีกลับ · และต่อให้ผ่าน agent แล้ว **ครูมนุษย์ยังต้องกดเผยแพร่เองอยู่ดี** (กฎ R14)

### สายเทค

```
impact-analyst (วิเคราะห์ก่อน) ──► next-dev (แก้) ──► qa-runner (ตรวจหลัง) ──► commit
```

**จุดสำคัญ:** `impact-analyst` **ห้ามแก้โค้ด** และ `qa-runner` **ห้ามแก้โค้ดเพื่อให้เทสต์ผ่าน** — ถ้าเทสต์ตก ให้รายงานแล้วส่งกลับ `next-dev`

### สายธุรกิจ

```
biz-analyst ──► (ตัวเลข/ข้อสรุป) ──► เจ้าของตัดสินใจ ──► อัปเดต BACKLOG.md
```

## กฎที่ทุก agent ต้องรู้ (สรุปจาก CLAUDE.md)

| กฎ | รายละเอียด |
|---|---|
| 🚫 **ลิขสิทธิ์** | โจทย์/เนื้อหา **แต่งเองทั้งหมด** ห้ามคัดลอกจากเอกสาร HQ หนังสือแบบฝึกหัด หรือเว็บใด ๆ |
| 🚫 **เด็กห้ามคุยกับ AI** | AI ใช้เฉพาะฝั่งครู/เจ้าของ |
| 🔒 **PDPA** | ข้อมูลที่ส่งให้ AI มีแค่ รหัส + ชื่อเล่น + สถิติ · ห้ามใส่ข้อมูลเด็กจริงใน repo |
| 🔒 **คะแนนคิดที่ server** | เหรียญแลกของจริงได้ → ห้ามให้ client หรือ AI ตัดสินคะแนนเอง |
| 📱 **UI เด็ก** | ปุ่มสูง ≥ 64px · ข้อความสั้น · ภาษาไทย · **ออกแบบมือถือ 360px ก่อน** (เปลี่ยนจากเดิมที่เอา tablet ก่อน — ดู EPIC E) |
| 🇹🇭 **ภาษา** | ตอบเป็นภาษาไทย รูปแบบ checklist กระชับ |

## วิธีใช้ใน sprint

1. เปิด `BACKLOG.md` → เลือก task ของ sprint นี้
2. ดูช่อง PIC → เรียก agent ตัวนั้น พร้อมบอกรหัส task (เช่น "ทำ C3")
3. agent ทำงานตาม skill ของตัวเอง แล้วส่งต่อตามสายงานข้างบน
4. ปิด sprint ด้วย `qa-runner` → commit → อัปเดตสถานะใน `BACKLOG.md`

**อย่าเรียก agent หลายตัวพร้อมกันบนไฟล์ชุดเดียวกัน** — ระบบนี้ผู้ใช้ 4 กลุ่มใช้ข้อมูลร่วมกัน แก้ชนกันแล้วหายาก
