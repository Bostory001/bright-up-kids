# คู่มือสอนออนไลน์ — คอร์ส Coding

ใช้แผนรายคาบเดิมใน `courses/` ได้ทุกคอร์ส ไฟล์นี้บอกว่า **ต้องปรับอะไร** เมื่อสอนผ่านวิดีโอคอล

> ยังไม่ได้ทดลองสอนออนไลน์จริง ตัวเลขเวลาและขนาดห้องเป็นข้อเสนอเริ่มต้น ควรปรับหลังนำร่อง

## 1. รูปแบบที่รองรับ

| แบบ | ทำอย่างไร | เหมาะกับ |
|---|---|---|
| **สดออนไลน์** (แนะนำ) | ครูสอนผ่านวิดีโอคอลตามตารางคาบ | B, C (ป.3–ม.3) |
| **สดออนไลน์ + ผู้ปกครองช่วย** | ผู้ปกครองนั่งข้าง ๆ ช่วยจัดอุปกรณ์/กดแอป | A (ป.1–2) |
| **เรียนเอง (คลิป)** | ดูคลิปสั้น + ทำใบงาน ครูตรวจงานทีหลัง | ทบทวน/ชดเชยคาบ (ต้องทำคลิปเพิ่ม) |
| **ผสม** | เรียนสดที่สถาบันบางคาบ ออนไลน์บางคาบ | ทุกคอร์ส |

## 2. ความเหมาะสมรายคอร์ส

| คอร์ส | ออนไลน์ได้ไหม | เหตุผล/ข้อควรระวัง |
|---|---|---|
| A1 Unplugged | ได้ แต่ต้องมีผู้ปกครองช่วย | กิจกรรมใช้ตัว/พื้น/การ์ด → ให้ผู้ปกครองพิมพ์ใบงานและตัดการ์ดไว้ล่วงหน้า |
| A2 ScratchJr | ได้ แต่ท้าทาย | ต้องมีแท็บเล็ตที่บ้าน เด็กเล็กไม่สามารถแชร์หน้าจอเอง → ให้ผู้ปกครองถ่ายหน้าจอหรือชูแท็บเล็ตให้ครูดู |
| B1–B4 Scratch | ได้ดี | ทำงานบนเบราว์เซอร์ ครูดูงานผ่านการแชร์หน้าจอหรือไฟล์ที่ส่งให้ |
| C1–C4 Python | ได้ดี | เด็กต้องติดตั้ง Thonny ก่อนคาบที่ 1 (ดูข้อ 4) |

## 3. ปรับโครงคาบสำหรับออนไลน์

- **ความยาว:** เด็กเล็ก (A) ไม่เกิน 40–45 นาที/คาบ · เด็กโต (B, C) 50–60 นาที พร้อมพัก 5 นาทีกลางคาบ
- **ขนาดห้อง:** A ≤ 5 คน · B ≤ 8 คน · C ≤ 10 คน (มากกว่านี้ครูตามงานไม่ทัน) · ถ้ามีผู้ช่วยสอน 1 คน เพิ่มได้ ~ 4 คน
- **โครงคาบ:** 10 นาทีทบทวน → 10 นาทีครูสาธิต (แชร์หน้าจอ) → 25–30 นาทีลงมือ (ครูเปิดห้องย่อย/เรียกตรวจทีละคน) → 5–10 นาทีโชว์งาน
- **ลดการบรรยายยาว:** เด็กนั่งดูหน้าจอนานจะหลุดสมาธิ → แบ่งเป็นช่วงสั้น 5–7 นาที สลับลงมือ
- **เช็กอินเสียง–กล้อง** ต้นคาบ และตกลงสัญญาณมือ (ยกมือ/ใช้แชท/ปุ่มยกมือ)
- **ตรวจงานระหว่างลงมือ:** ให้เด็กแชร์หน้าจอ หรือถ่ายภาพโค้ดส่งในแชท ครูเรียกดูตามลำดับชื่อ
- **งานในห้อง:** ให้เด็กบันทึกไฟล์ (`.sb3` สำหรับ Scratch, `.py` สำหรับ Python) แล้วส่งให้ครูทางช่องทางที่สถาบันกำหนดหลังจบคาบ

| รายการ | รายละเอียด |
|---|---|

| อินเทอร์เน็ต | เสถียร (วิดีโอคอลพร้อมเปิดเว็บ) |

## 5. เครื่องมือสำหรับห้องเรียนออนไลน์

| หน้าที่ | ตัวเลือก | หมายเหตุ |
|---|---|---|
| วิดีโอคอล | Google Meet / Zoom / ฯลฯ | **ยังไม่ได้ตรวจ** ฟีเจอร์ ราคา และข้อจำกัดเวลา/จำนวนคนของแต่ละเจ้า — ตรวจที่เว็บทางการก่อนเลือก |
| กระดานร่วม | กระดานในแพลตฟอร์มคอล (ถ้ามี) หรือกระดาษ + กล้อง (ยังไม่ได้ตรวจว่าตัวไหนใช้ฟรี) | ใช้ในคอร์ส A และอธิบายลำดับขั้นตอน |
| ส่งงาน/เก็บงาน | ระบบหลังบ้านของสถาบัน/LINE/อีเมลผู้ปกครอง | ตกลงช่องทางเดียวทั้งสถาบัน |
| Scratch ร่วม | ให้เด็กบันทึกไฟล์เอง ครูไม่ต้องใช้บัญชีออนไลน์ | ถ้าไม่สมัครบัญชี ลดความเสี่ยง PDPA |

## 6. PDPA และความปลอดภัยออนไลน์

- ได้รับความยินยอมจากผู้ปกครองก่อนเริ่มเรียน ครอบคลุม **การเปิดกล้อง** **การบันทึกคาบ** และการเผยแพร่ผลงาน
- **ไม่บันทึกคาบ** เว้นแต่จำเป็นและแจ้งผู้ปกครองแล้ว ถ้าบันทึกให้เก็บในที่จำกัดสิทธิ์ ไม่เผยแพร่สาธารณะ
- ใช้ชื่อเล่นบนหน้าจอ ไม่ใช้นามสกุล ไม่ใช้รูปประจำตัวจริงของเด็ก
- ลิงก์ห้องเรียน: ใช้รหัส/ห้องรอ (waiting room) ให้ครูอนุมัติทุกคน ไม่โพสต์ลิงก์สาธารณะ
- ครูไม่เรียนตัวต่อตัวโดยไม่มีผู้ปกครอง/ผู้ช่วยในห้อง หรือเปิดให้ผู้ปกครองเข้าสังเกตการณ์ได้
- ไม่ให้เด็กโพสต์งานขึ้นชุมชนสาธารณะ (เช่นเว็บแชร์ของ Scratch) โดยไม่ผ่านผู้ปกครอง
- ให้เด็กใช้บัญชี/อีเมลเด็กตามกฎของแพลตฟอร์ม (ตรวจเงื่อนไขอายุของแต่ละแพลตฟอร์มก่อนใช้)

## 7. ข้อควรระวังเฉพาะ A (ป.1–2)

- เด็กเล็กต้องมีผู้ปกครองนั่งด้วยทุกคาบ
- ใช้ "เกมใช้ร่างกาย" ได้แต่ให้ทำตามหน้ากล้อง (ผู้ปกครองช่วยจัดพื้นที่)
- คาบสั้น และใช้ภาพ/การ์ดเยอะ

## 8. เรียนเอง (self-paced) — ถ้าจะเพิ่ม

- ตัดแต่ละคาบเป็นคลิป 5–8 นาที + ใบงาน + เฉลยให้ผู้ปกครอง
- ตอนนี้เว็บของสถาบันมีระบบ "คลิปสอน" แต่ **ยังไม่ได้ตรวจ** ว่ารองรับวิชา Coding ได้โดยไม่แก้โค้ด (วิชาในระบบเป็น 4 วิชา) ถ้าจะใช้ต้องวิเคราะห์ผลกระทบ `types.ts` ก่อน
- คลิปทำได้ด้วยสกิลที่มีในโปรเจกต์ (เช่น กระดานดำชอล์ก) แต่ต้องตรวจเนื้อหาก่อนเผยแพร่
